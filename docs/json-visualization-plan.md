# Raycast JSON 可视化扩展：功能分析与实施方案

> 状态：首版产品范围已逐项确认并经用户整体确认；尚未实现。调研日期：2026-11-02。技术可行性和性能边界须按第 9 节实测。

## 1. 目标与边界

开发运行于 Raycast 的本地优先 JSON 工具，让用户输入 JSON 后查看结构、查找、格式化和转换。运行时 JSON 数据处理不依赖网络或远程服务；不讨论主题、字体及视觉风格。此阶段只分析和写方案，不新增扩展代码。

“离线”指扩展命令执行期间，输入、解析、搜索、转换和展示不需要网络，也不主动发送 JSON、路径、搜索词或遥测。开发时安装依赖、Raycast 本身的更新或将来发布扩展可能联网，不能等同于扩展运行时发起请求。Raycast 扩展并无网络沙箱，离线保证必须依赖代码、依赖审查和验证，不能仅依靠平台权限设置。

## 4. Raycast 文档与设计约束

1. [文件结构](https://developers.raycast.com/information/file-structure)与 [Manifest](https://developers.raycast.com/information/manifest)：扩展以 `package.json` 声明命令，每个命令有对应入口；交互界面使用 `view` 命令。推荐初版一个主命令，避免在根搜索中散落多个入口。
2. [Form](https://developers.raycast.com/api-reference/user-interface/form) 支持 `Form.TextArea` 和校验，适合录入多行文本；[Clipboard](https://developers.raycast.com/api-reference/clipboard) 提供读取和复制。建议用户显式选择从剪贴板读取，避免打开即读取；空剪贴板、非文本和失败须明确提示，原有输入不丢失。
3. [List](https://developers.raycast.com/api-reference/user-interface/list) 提供搜索、列表和分页，也允许自定义过滤。可将节点显示为列表项，用动作展开/收起和复制；搜索要自定义才能明确匹配路径、键和值。分页不能消除整个解析树占用的内存，平台可能停止继续分页。
4. [Actions](https://developers.raycast.com/api-reference/user-interface/actions) 与导航适合键盘操作和进入子视图。应在原生组件内做结构浏览，不假设浏览器式任意 HTML、编辑器或交互式树控件可直接嵌入；原生列表能否满足深层树可读性必须通过实际原型验证。
5. [生命周期](https://developers.raycast.com/information/lifecycle)：命令退出时卸载，且有内存限制。初版数据仅保存在会话内；退出后不承诺恢复。不要启用表单草稿或自动持久化输入，以减少敏感 JSON 留存。
6. [安全](https://developers.raycast.com/information/security)和 [Storage](https://developers.raycast.com/api-reference/storage)：扩展可访问 Node 文件及网络，`LocalStorage` 位于 Raycast 的本地加密数据库且不适合大量数据。初版不自动保存 JSON、历史或缓存，也不输出原文到日志；用户主动导出是明确的文件写入例外。复制后系统剪贴板及其历史仍可能留存内容，扩展不能保证其他应用的处理方式。
7. [开发入门](https://developers.raycast.com/basics/getting-started)当前要求 Node.js 22.14+、npm 7+；创建与导入扩展的开发命令要求登录。开发依赖安装和 Raycast 平台行为不属于离线运行承诺。

## 5. 首版交互方案

### 5.1 输入与查看

1. 打开 `JSON Viewer` 命令，进入输入表单。用户手动粘贴，或显式执行“从剪贴板读取”。不自动读取选中文本、文件、浏览器标签或剪贴板历史。
2. 提交时严格解析 JSON；空输入、非 JSON 和解析失败均保持原输入并给出错误。尽可能展示解析器可提供的位置，但不能承诺所有运行时都有一致的错误行列信息。
3. 成功后默认显示格式化文本，可切换到树列表；树列表：每项展示键或数组下标、类型、简短值或子项数；根节点也支持标量、`null`、空数组和空对象。选中容器通过动作展开或收起；选中任意节点可复制值或路径。退出节点视图返回输入时保留本次输入。
4. 列表操作包括展开/收起当前节点、展开/收起全部（受规模限制）、复制节点 JSON、复制路径、复制完整格式化 JSON、复制压缩 JSON、重新编辑输入。动作名称与快捷键在实现时遵循 Raycast 约定并避免冲突。

### 5.2 搜索与统计

- 用户确认提供节点文字搜索和全文正则搜索两种模式。节点搜索采用大小写不敏感的字面子串匹配，对键、标量值的显示文本和路径匹配；不解释正则或 JSONPath。搜索结果按文档遍历顺序列出，清空后恢复原树展开状态。定位结果应展开祖先并选中节点；若 Raycast 无法稳定实现选中，原型阶段改为进入对应节点的详情，不能声称自动定位已实现。
- 全文正则搜索与节点搜索分开：搜索用户选择的原始输入或格式化结果的完整文本（包括键、值、标点和空白），默认搜索当前正在查看的文本，可切换原文与格式化结果；原文即使不是合法 JSON 也可搜索，格式化结果仅在解析成功后可选；明确显示当前搜索对象，避免结果位置与文本版本混淆。
- 用户确认使用 JavaScript `RegExp` 正则语法，不再要求 Vim 正则兼容，也不为 Vim 引入专用引擎。用户直接输入表达式本体，例如 `name|id`，不要求斜杠包裹；默认区分大小写，提供忽略大小写切换。非法表达式明确报错，不自动转为字面搜索；表达式和搜索内容不得发送至远程服务。
- JavaScript 同步正则可能发生灾难性回溯；必须验证本地可中断的隔离执行方式及打包兼容性，并覆盖非法表达式、Unicode、跨行、零长度匹配及复杂表达式超时。若无法可靠中断，不能以无保护的同步执行方式交付。
- 结果按文本位置顺序显示匹配摘要及 1 起始行列，支持查看上一项、下一项以及匹配总数；在 Raycast 中若无法在原生文本控件中定位或高亮，使用独立匹配列表及上下文片段，不声称已支持编辑器内高亮。跨行匹配遵循 JavaScript `RegExp` 及所选标志的规则，零长度匹配必须推进索引，避免无限循环。非法正则显示错误并保留输入；无结果明确提示。
- 搜索控件、匹配结果和原文必须有独立可读空间；提交正则或切换匹配项后不得遮挡内容或匹配结果。特别验证单行、三行及少量匹配时首行与末行均可读，关闭搜索后仍能查看原文。Raycast 若不能提供可靠的原位显示，则使用独立结果视图。
- 全文检索必须设置输入规模、匹配数量和执行时间预算，并以可中断的隔离执行环境实现，避免灾难性回溯冻结命令；不能依赖与同步正则处于同一事件循环的计时器实现超时。先验证 Raycast 运行环境是否支持该隔离机制；如果不能保证中断，正则功能不得以无保护的同步执行方式交付。达到限制时标明结果不完整或超时，不能误报无匹配。统计行列、换行及 Unicode 单位在实现与界面上统一定义，覆盖 CRLF 和跨行匹配。
- 行数定义：空文本为 1 行，与截图中的空状态一致；非空文本按 `\n` 分隔计算，末尾换行产生一个空行；CRLF 计作一次换行。字符数以 Unicode 码点计数，避免把 JavaScript UTF-16 `length` 误称字符数；仅显示当前文本的行数和字符数，不展示字节数，切换原文或结果时更新。
- 截图只证明空状态为 1 行、0 字符，不能证明参考插件对 Unicode、换行或结果区的统计口径；上述统计定义是本方案选择。
- 路径采用 JSON Pointer（RFC 6901）：根路径为空字符串，键中的 `~` 和 `/` 分别转义为 `~0` 和 `~1`；数组路径使用十进制下标。界面须对根路径提供可辨识的显示，复制仍为规范空字符串。

### 5.3 格式化、压缩与转义

- 格式化：用户确认固定两个空格缩进，输出合法 JSON；压缩：输出无可省略空白的合法 JSON。两者针对解析后的值，复制为显式用户动作。
- 转义：先严格校验输入为合法 JSON，校验失败显示错误并保留原文；成功后将原始输入编码为完整标准 JSON 字符串字面量，包含外层双引号。例如原文 `{"a":1}` 转为 `"{\"a\":1}"`，冒号原样保留。去转义只接受带外层双引号的合法 JSON 字符串，输出解码后的文本；无效输入显示错误并保留原文。
- 标准 `JSON.parse` / `JSON.stringify` 存在重要语义限制：超出安全整数范围的数值可能精度丢失；重复键解析后只保留最后一个；数值表示、空白及对象键顺序可能改变。首版必须先确定策略：优先评估能保留原始数值与重复键的解析方案；若选原生解析，必须在执行有损转换前检测并明确提示或拒绝，不得默默输出错误数据。不得用 `eval` 或宽松修复替代严格 JSON。

### 5.4 本地导出与布局

- 在结果视图提供“Export JSON”，导出当前有效的格式化或压缩 JSON，默认导出格式化结果，也可选择压缩结果，用户选择本地目标路径；不使用未经用户选择的默认目录，也不通过网络下载。导出内容来自当前成功解析的输入，转换失败不得沿用上次结果冒充当前结果。
- 保存路径选择与写入方式先用 Raycast 原生 API 做可行性验证；保存失败展示原因且保留内容。用户确认目标已存在时询问是否覆盖，取消时保留原文件；不能静默覆盖。若平台无法提供可靠的保存位置选择与覆盖确认，先保留复制能力并明确记录导出为待实现，不用未经确认的固定路径代替。
- 用户说明布局开关用于关闭左侧输入区。Raycast 首版以结果视图实现专注查看，并提供返回输入视图的动作；在原生视图中保留输入，不能承诺复刻双栏及其开关。

## 6. 技术拆分与数据流

用户明确要求项目的应用源码、界面、业务逻辑和自行编写的测试均使用 TypeScript（界面采用 TSX），结合 React + `@raycast/api`；JavaScript `RegExp` 指运行时正则语法，并不改变源码语言。依照 Raycast 模板及当前官方工具链建立清单和脚本；工具链要求的 JSON 配置、生成文件及第三方依赖不属于自行编写的项目源码。不预先引入网络、分析、远程字体或浏览器依赖。核心处理保持为独立纯函数，与 UI 解耦，便于离线测试。

```text
手动输入 / 用户主动读取剪贴板 → 输入边界与大小检查
  ├→ 原文全文正则搜索 / 原文统计（无需合法 JSON）
  └→ 严格解析 / 无损风险检查 → 文档模型（类型、路径、子节点）
      → 结构浏览 / 节点搜索 / 格式化 / 压缩 / 结果搜索与统计
      → Raycast List 与 Action → 用户主动复制或导出结果
```

建议模块职责：命令与输入表单；解析及错误映射；节点遍历与 JSON Pointer；搜索与展开状态；格式化、压缩和字符串转换；统计；Raycast 视图。文件名和最终边界以模板和原型为准，避免提前搭建复杂框架。

性能：不对输入每次按键立即解析；提交后处理。树遍历使用迭代方式或明确深度限制，避免栈溢出；仅构建可见行，搜索和批量展开应有限制。初始设定输入上限、深度、节点数及列表显示量为**待测参数**，在真实 Raycast 环境用代表性样本测量后写入产品提示与测试；超过上限时保留原始输入，解释限制，不截断数据后假装成功。内存和响应时间无法在当前空仓库中事先保证。

## 7. 验收与验证计划

- **正确性**：对象、数组、根标量、空值、空容器、中文、emoji、转义字符、特殊键（含 `/`、`~`、空键）、深层和大数组；验证节点类型、路径与展开状态。
- **异常与数据完整性**：空文本、无效 JSON、尾逗号、错误转义、重复键、超安全整数、极大指数、深层与超限输入；检查错误提示、输入保留以及无静默精度损失。格式化和压缩结果重新解析后语义一致；字符串转义/反转义往返一致。
- **搜索和统计**：节点搜索覆盖键、值、路径、重复命中、无结果和清空恢复；全文正则覆盖 JavaScript 正则语法、分隔符规则、分组、字符类、键、值、标点、跨行、大小写、非法表达式、零长度匹配、结果上限和复杂表达式超时；实机检查回车检索后单行及三行内容和匹配结果均不被遮挡，并验证切换原文/格式化文本后的行列位置；统计覆盖 CRLF、末尾换行、空文本、中文及 emoji 的字符计数。
- **交互**：实际 Raycast 中验证输入、粘贴、错误返回、展开收起、搜索定位、复制、导出、覆盖确认、写入失败、再次编辑及退出后的会话行为；验证键盘动作、空状态和大数据边界。单元测试不能替代实机交互验收。
- **离线**：审查源码及依赖的网络调用、运行时脚本与遥测；在断网条件下测试所有首版动作，并结合进程级网络观察确认运行时无主动外连。记录测试环境、工具和覆盖范围；断网成功本身不能证明从未尝试联网。依赖安装、Raycast 更新等平台流量与扩展运行时请求区分记录。
- **工程检查**：按照实际生成的项目脚本运行测试、格式、lint、构建；在 Raycast 中导入并运行。具体命令以最终 `package.json` 为准，不提前声称已通过。

### 10.1 数据完整性技术决策门槛

不得仅靠解析后的 JavaScript 数值检查大整数或重复键：精度和重复键信息在 `JSON.parse` 时就可能丢失。实现阶段先验证采用支持保留源 token 和重复键的严格 JSON 解析器，或实现具备相同性质的解析流程；评估依赖的许可证、运行时网络行为及包体积。若无法可靠保留，必须在数据丢失之前检测并拒绝对应输入；如果不能可靠检测，相关转换功能不能交付。节点身份不能只由 JSON Pointer 唯一确定：重复键可产生相同路径，内部需使用独立节点标识，并在 UI 标明歧义，复制路径不暗示能唯一定位。

### 10.2 导出与离线验收样例

- 导出前选择格式化或压缩结果及目标路径；写入成功后读取文件并比较字节内容。取消保存、路径无权限、已存在文件选择不覆盖、写入失败都不得丢失输入或覆盖目标。
- 使用包含中文、换行、转义字符及大整数的测试样本；断网运行输入、查看、节点搜索、全文正则搜索、折叠、格式化、压缩、转义、去转义、复制和导出。分别记录离线结果与网络观察结果；如无法归因 Raycast 宿主与扩展请求，报告观测局限，不宣称已经证明无外连。


## 11. 已确认的首版产品规则

- 采用 TypeScript 编写应用源码和测试，界面使用 TSX；运行时本地处理，不上传数据，不考虑主题和字体。
- 输入通过手动粘贴或用户主动读取剪贴板；不自动读取、不导入文件；关闭命令后不自动保存输入。
- 成功解析后默认显示格式化文本，可切换结构视图；结构视图初始展开根节点并支持按需展开、收起和批量操作。接受 Raycast 原生页面切换。
- 格式化固定两个空格；压缩生成紧凑 JSON。尽量无损保留大整数、高精度数字与重复键，不能保证时提示并拒绝处理，保留原文。
- 转义只接受合法 JSON，校验后将原始输入文本编码为完整标准 JSON 字符串，包含外层引号且冒号原样保留；去转义只接受完整合法的 JSON 字符串，输出解码文本。出错时保留原文并提示。
- 提供节点文字搜索与全文 JavaScript 正则搜索；正则直接输入表达式本体，默认区分大小写，可切换忽略大小写。默认搜索当前正在查看的文本，可切换原文与格式化结果；原文无效 JSON 也可搜索。回车后单行、三行内容和结果不得遮挡。
- 只显示当前文本的行数和字符数；本方案按 Unicode 码点计字符，空文本为一行，CRLF 算一次换行。
- 用户主动导出时默认格式化结果，可选择压缩结果；用户选择本地位置和文件名，遇到同名文件先询问是否覆盖，取消时保留原文件。
- 方案文档经用户明确授权纳入提交；实施代码按聚焦的中文 Conventional Commits 管理。

技术方案和验证门槛见第 9、10 节，涉及平台能力或具体性能参数时以实测为准。
